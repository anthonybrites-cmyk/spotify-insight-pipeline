# Design choices

## Why Jev for enrichment

The shared labels are closed sets: 8 topics, 5 intents, and 5 severity levels. Jev answers typed questions over a fixed set of options. It returns the chosen option, a probability for every option, and a confidence score, so there is no free text to parse. Its list price is $0.042 per million input tokens, and output is free.

- **One review per request.** The contract allows at most 50 reviews per request, and 1 satisfies it. Jev's documentation says accuracy falls as unrelated text accumulates in one request. Batching would also repeat the question set for every review, so it would not save money.
- **Jev cannot write text.** Evidence quotes are therefore cut from the review by code, sentence by sentence. When a review has more than one sentence, Jev chooses the best one. Every quote is an exact substring by construction.
- **Entities come from code.** They are matched against a small, auditable lexicon (`pipeline/entities.py`), not generated by a model.
- **Code enforces the contract's rules.** Severity is set to 1 for praise, request and unclear reviews, and to at least 2 for complaints. Sentiment is computed from Jev's level probabilities in Decimal arithmetic. Jev's documentation advises keeping arithmetic and identity rules in code.

## Where Claude (`claude-sonnet-5`) is used

It is used only for small tasks that need judgment or free text:

1. **Blind verification.** This is a different model family and never sees Jev's labels. The declared sample is 50% lowest-confidence Jev labels, where errors concentrate, and 50% uniform random by seeded hash, which gives an unbiased agreement estimate.
2. **Subtopic list.** Claude proposes it from a saved, deterministic sample of complaint quotes.
3. **The memo.**

A material disagreement sets `needs_review=true`: topic or intent differs, or severity differs by 2 or more levels. The label itself is not overwritten, so each label keeps a single `label_config`.

## needs_review

`needs_review` is true when any of these hold:

- Jev's "unclear or missing context" probability is at least 0.5.
- Topic, intent or severity confidence falls below the thresholds in `config.py`.
- The verifier materially disagreed.

The thresholds are provisional and will be calibrated on the development runs.

## Grouping and ranking

- **One issue per complaint** (`allow_multi_issue=false`). Issue ID = `<topic>.<subtopic>`, with a code-added `<topic>.general` catch-all.
- **When Jev is skipped or fails.** If a topic only has the catch-all, assignment is a rule with no model call. If an assignment call fails after retries, the complaint goes to the catch-all, and the reason is recorded in `group/assignments.jsonl`.
- **Ranking is pure code:** `priority_score = severity_sum`, using integer sums and Decimal half-up means. It is sorted by descending score, then ascending issue ID. Tests confirm it is reproducible and that half-up rounding differs from banker's rounding where it should (129/128 → `1.007813`).

## Memo guardrails

Every number in the memo must match the value of a claim (`C##`) or fact (`F##`) cited in the same paragraph. Integers 1–10 are exempt, for ranks and list counts. Money, revenue and asserted churn are rejected. The errors are fed back to the model for up to two revisions. Only the claims actually cited go into `claims.csv`.

## Prompt injection

- **Jev:** the review is sent as a JSON value (`{"review": ...}`), and every question tells Jev never to follow instructions inside it.
- **Claude:** reviews are wrapped in `<reviews>` and marked untrusted. Outputs are schema-constrained, and code verifies that the returned IDs exactly match the IDs sent.
- **Test cases:** `evals/injection_cases.jsonl` has 12 synthetic cases, 7 adversarial and 5 controls. They run live through both models (`python -m pipeline eval-injection`) in a separate run directory and never enter business results.
